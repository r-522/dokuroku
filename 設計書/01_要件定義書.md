# 01_要件定義書

## 1. プロジェクト概要

読録は、読んだものから得た個人的な感想・考察・解釈をMarkdown形式で残し、あとから検索できる個人向けWebアプリケーションである。管理対象は本に限定せず、技術記事、ブログ、Web記事、複数資料を読んで考えた内容を含む。

## 2. 背景

汎用メモツールは多機能である一方、記録時に分類や整理を求められやすい。読録では、読後に残った考えを失わずに保存することを優先し、入力負担を減らす。

## 3. 目的

- 自由な文章入力だけで記録を残せる。
- 保存した記録を一覧と検索で探せる。
- AIを使う場合でも、本文の省略・要約・改変を防ぐ。
- Go、React、PostgreSQLによるWebアプリの基本構造を理解しやすくする。

## 4. 想定ユーザー

- 個人利用者1名。
- 読書、技術記事、Web記事から得た考えを残したい人。
- Webアプリの仕組みを理解しながら開発したい人。

## 5. 利用シーン

- 読書後に感想を自由入力する。
- 技術記事を読んだあと、理解したことや疑問を残す。
- 複数URLを含む記録を残す。
- 過去の記録をキーワードで検索する。
- 記録の内容を編集または削除する。

## 6. 機能要件

| ID | 要件 |
| --- | --- |
| FR-001 | 簡易パスワードで利用開始できる |
| FR-002 | 自由入力から記録を作成できる |
| FR-003 | 明示されたMarkdown見出しをタイトルとして扱える |
| FR-004 | タイトル未指定時はAIで一覧識別用タイトルを生成できる |
| FR-005 | AI失敗時も本文を失わず「無題」で保存できる |
| FR-006 | ユーザー入力に含まれるURLをGo側で機械的に抽出できる |
| FR-007 | 複数URLを1記録に保存できる |
| FR-008 | 記録一覧を表示できる |
| FR-009 | 記録をキーワード検索できる |
| FR-010 | 記録を編集できる |
| FR-011 | 記録を削除できる |
| FR-012 | 本文全文はDBに省略せず保存する |

## 7. 非機能要件

- 個人利用として十分な応答速度を保つ。
- AI API障害時もDB保存処理を可能な限り継続する。
- Go標準ライブラリ中心で理解しやすい構成にする。
- 外部ライブラリは必要最小限にする。
- GCP上ではCloud RunとCloud SQL for PostgreSQLを想定する。

## 8. UI/UX要件

- 一覧画面を中心に、新規作成、検索、編集、削除を行う。
- AIチャット風UI、派手なグラデーション、過度なカードUIは避ける。
- 落ち着いた色、少ない画面遷移、少ない入力項目を優先する。
- 一覧ではプレビューを省略してよいが、DB本文は省略しない。

## 9. AI要件

- Claude Haiku 4.5を使用する。
- AIの役割は、タイトル判定、タイトル生成、Markdown構造化、JSON化の補助に限定する。
- AIは本文を要約、省略、添削、思想変更してはならない。
- AIは入力に存在しないURLを生成してはならない。
- AIレスポンスはアプリケーション側で検証する。

## 10. データ要件

保存する基本情報は以下に限定する。

| 項目 | 内容 |
| --- | --- |
| `id` | 記録ID |
| `title` | 一覧識別用タイトル |
| `content` | Markdown本文全文 |
| `urls` | 入力本文から抽出したURL配列 |
| `created_at` | 作成日時 |

## 11. 認証・セキュリティ要件

- 本格的なユーザー管理は行わない。
- 簡易パスワードを環境変数`APP_PASSWORD`で管理する。
- パスワードはソースコードにハードコードしない。
- インターネット公開時に誰でも利用できる状態を避ける。

## 12. 制約事項

- フェーズ1では実装コードを作成しない。
- Webフレームワークを使用しない。
- Reduxなど高度な状態管理ライブラリを導入しない。
- DBテーブル名には`BOOK_`接頭辞を付ける。

## 13. 今回実装しないもの

- ユーザーアカウント管理
- タグ、カテゴリ、評価、著者、出版社、ジャンル
- 複雑な権限管理
- 高度な全文検索エンジン
- AIチャット機能
- SNS共有機能

## 14. 将来的に検討可能なもの

必要性が明確になった場合のみ、以下を検討する。

- PostgreSQL全文検索の改善
- エクスポート機能
- Markdown表示体験の改善
- バックアップ手順の整備
