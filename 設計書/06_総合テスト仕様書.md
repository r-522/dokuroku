# 06_総合テスト仕様書

## 1. 方針

総合テストは、実際のユーザー操作に近い流れで読録全体を確認する。単に正常系だけでなく、AI障害、空入力、長文、日本語Markdown、複数URLを含む利用シナリオを確認する。

## 2. 総合テストケース

| ID | シナリオ | 手順 | 期待結果 |
| --- | --- | --- | --- |
| ST-001 | 初回利用 | パスワード入力後、一覧画面を開く | 一覧画面が表示される |
| ST-002 | H1タイトル作成 | `# 月人の野望`を含む本文を保存 | titleが`月人の野望`になり本文が保存される |
| ST-003 | タイトルなし作成 | H1なし本文を保存 | AI生成タイトルまたは`無題`で保存される |
| ST-004 | AI失敗 | AI APIを失敗させて保存 | 入力本文を失わず保存される |
| ST-005 | 複数URL | 3つのURLを含めて保存 | 3つのURLが`urls`に保存される |
| ST-006 | 検索 | 保存済み本文の語句で検索 | 該当記録が一覧に表示される |
| ST-007 | 編集 | 保存済み記録を編集 | 編集後本文が省略されず保存される |
| ST-008 | 削除 | 保存済み記録を削除 | 一覧とDBから削除される |
| ST-009 | 空入力 | 空または空白のみで保存 | 保存されずエラー表示される |
| ST-010 | 不正入力 | 壊れたJSON相当のAPIリクエスト | 400を返しDBに保存しない |
| ST-011 | 長文 | 長い日本語本文を保存 | タイムアウトせず本文全文が保存される |
| ST-012 | 日本語Markdown | 見出し、箇条書き、URLを含む本文 | Markdownとして保存・表示できる |
| ST-013 | URLなし | URLを含まない本文を保存 | `urls`は空配列になる |
| ST-014 | 再ログイン | CookieなしでAPIへアクセス | 401になりパスワード画面へ戻る |

## 3. 重点確認項目

- DBに保存された`content`が入力本文から不当に省略されていない。
- 一覧プレビューの省略がDB保存内容に影響しない。
- AIが使えない状況でも作成体験が破綻しない。
- UIが一覧中心で、AIチャット風になっていない。
- タグ、カテゴリ、ユーザー管理など未採用機能が紛れ込んでいない。

## 4. Codex設計レビュー

### 4.1 レビュー結果

| 確認項目 | 結果 | メモ |
| --- | --- | --- |
| 要件と基本設計に矛盾がないか | OK | 基本情報は`id/title/content/urls/created_at`に限定した |
| 基本設計と詳細設計に矛盾がないか | OK | Handler/Service/Repository/AI Harnessの責務が一致している |
| APIとDB設計が一致しているか | OK | APIレスポンスはDBカラムに対応している |
| FrontendとBackendの通信仕様が一致しているか | OK | `fetch`とJSON APIで統一した |
| AIの責務が過剰でないか | OK | URL抽出や保存判断はGo側に置いた |
| AIが本文を改変する可能性がないか | 要注意 | 検証失敗時はAI結果を破棄し原文保存する設計にした |
| URLをAIが生成する可能性がないか | OK | 保存URLはGo側抽出結果のみ使用する |
| AI失敗時に入力内容を失わないか | OK | `無題`と原文保存でフォールバックする |
| 認証方式に問題がないか | OK | 個人利用の簡易門番としてCookie方式を採用する |
| セキュリティ上の重大な問題がないか | 要注意 | 本格認証ではないため公開範囲とHTTPS前提を実装時に確認する |
| テストケースが要件を十分にカバーしているか | OK | 単体、結合、総合でAI失敗とURLを重点化した |
| 不要な機能が入り込んでいないか | OK | タグ、カテゴリ、ユーザー管理を除外した |
| 不要なライブラリが追加されていないか | OK | Router/Redux/検索エンジンは不採用とした |
| Go学習目的に対して依存しすぎていないか | OK | `net/http`と`database/sql`中心にした |
| React理解目的に対して依存しすぎていないか | OK | React標準stateと`fetch`中心にした |
| UIが過度に複雑でないか | OK | 一覧中心の単一画面にした |
| UIがAI的・派手でないか | OK | 落ち着いたシンプルUI方針にした |

### 4.2 レビュー結論

フェーズ1の設計は、読録の価値観である「必要十分、理解できる、保守できる」に沿っている。フェーズ2へ進む前に、ユーザーが設計書を確認し、AIによるMarkdown構造化の許容範囲と簡易認証の公開リスクを最終確認する必要がある。
