# 05_結合テスト仕様書

## 1. 方針

結合テストでは、React、Go API、AI Harness、Repository、PostgreSQLの接続点を確認する。AI APIは実APIとモックの両方を想定し、通常CIではモックを使う。

## 2. テストケース

| ID | 結合範囲 | シナリオ | 期待結果 |
| --- | --- | --- | --- |
| IT-AUTH-001 | React → Go | 正しい簡易パスワードでログイン | Cookieが保存され一覧画面へ進む |
| IT-AUTH-002 | React → Go | 誤ったパスワード | エラーメッセージを表示し一覧へ進まない |
| IT-NOTE-001 | React → Go → DB | H1タイトル付き作成 | H1がtitle、本文全文、URL配列が保存される |
| IT-NOTE-002 | React → Go → AI → DB | タイトルなし作成AI成功 | AI生成タイトルと本文全文が保存される |
| IT-NOTE-003 | React → Go → AI失敗 → DB | AIタイムアウト | `無題`で本文全文が保存される |
| IT-NOTE-004 | React → Go → DB | 複数URL入力 | 入力に存在する複数URLのみ保存される |
| IT-NOTE-005 | React → Go → DB | 一覧取得 | 登録日降順で記録が返る |
| IT-NOTE-006 | React → Go → DB | 検索 | title/contentに一致する記録だけ返る |
| IT-NOTE-007 | React → Go → DB | 編集 | contentとurlsが更新される。created_atは変わらない |
| IT-NOTE-008 | React → Go → DB | 削除 | 一覧から対象が消える |
| IT-AI-001 | Go → AI Harness | AIが不正JSONを返す | AI結果を破棄しフォールバックする |
| IT-AI-002 | Go → AI Harness | AIが本文を欠落させる | AI結果を破棄し原文を保存する |

## 3. データフロー確認

作成時の主要フローを確認する。

```text
React textarea
  ↓ raw_text
Go Handler
  ↓ request context
Note Service
  ├─ URL Extractor
  ├─ H1 Title Detector
  ├─ AI Harness(optional)
  └─ Repository
        ↓
PostgreSQL BOOK_notes
```

## 4. 環境

- PostgreSQLテストDBを使用する。
- `APP_PASSWORD`はテスト用値を環境変数で設定する。
- AIは通常モックを使い、手動確認時のみ実APIを使う。

## 5. 判定基準

- AI失敗時でも本文保存が成功する。
- URL保存結果にAI生成URLが混入しない。
- APIレスポンスとFrontendの期待フィールドが一致する。
- DBスキーマが詳細設計の`BOOK_notes`と一致する。
